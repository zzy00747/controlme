# 需求文档:AI 自律计划助手(暂定名)

> 状态:草案(待评审)
> 版本:v0.1
> 产品形态:Android 原生 App
> 核心假设:用户用中文自然语言随口描述安排,系统自动整理为结构化每日计划,经「对话式确认」后落地执行,并支撑软约束自律闭环。

---

## 1. 背景与问题

用户在以下场景存在自控与计划困难:

- **碎片时间失控**:公交 / 地铁 / 走路等通勤时间,易被无意识刷手机填满,无法利用。
- **强制性任务防分心**:睡觉、学习等必须专注的时段,总是不自觉地拿起手机看娱乐内容。
- **计划整理困难**:对自身待办没有清晰结构,希望用自然语言描述即可得到结构化安排,而非手动逐条建待办。
- **缺乏复盘闭环**:专注结束后、每天结束时,缺少"记录做了什么 / 回看今日"的机制,容易陷入连续低效学习后彻底停摆。

期望的解决路径:用一个 Android App,以 **「自然语言 → 每日计划」为核心差异点**,配以软约束专注计时与复盘,帮助用户掌控一天。

## 2. 产品定位(一句话)

用中文自然语言描述安排,自动整理成可执行的结构化每日计划;解析结果先停留在对话中,**经用户确认后才正式写入**,并围绕计划提供轻量的专注与复盘闭环。

## 3. 目标用户与核心场景

| 场景 | 描述 | 产品对应能力 |
| --- | --- | --- |
| 规划当日/明日 | 用户说一句「明天上午医院复查,下午写周报,晚上8点跑步」 | 自然语言解析、生成计划 |
| 通勤碎片时间 | 公交/地铁/走路时想用好碎片时间 | 场景化计划、剪贴板快速录入 |
| 专注任务防分心 | 睡觉/学习高峰不希望无意识刷手机 | 软约束专注计时(远期强锁机) |
| 随手记录不排期 | 一条提醒、一个地址,不一定要进计划 | 备忘录模式 |
| 每晚复盘 | 睡前回看今日做得好的/值得鼓励的 | 晚间复盘提醒 |

## 4. 非目标(本版本明确不做)

- 不做系统级强锁机、不拦截/过滤特定流量(远期)。
- 不做慈善捐款退出机制(远期,涉及支付/托管/信任)。
- 不做离线本地 LLM 解析。
- 不做 iOS / 桌面包。

## 5. 核心功能需求

### 5.1 对话式自然语言 → 计划(核心)

一次输入的闭环:

```
输入自然语言 → LLM 解析在对话流中产出计划草稿(未正式写入)
       ↓ 多轮澄清(改时间/补时长/冲突提醒)
  用户明确确认 → 正式写入结构化计划
       ↓
  打勾执行 · 看进度 · 每日重复
```

关键规则:

- **未确认前不落库**:对话中产出的计划草稿只存在于对话上下文,不进入正式计划表;用户明确说「确认/就这样/加上」等才写入。
- **多轮对话协作**:用户可随时补充、修改、追问,LLM 基于对话上下文持续调整草稿,不做一次性硬解析。
- **冲突/时序提醒是对话能力**:LLM 发现计划间时间冲突时,在对话中主动提示并给建议(而非硬校验报错)。
- **可当作备忘录**:用户不想排期的内容,确认后存入备忘录而非计划。

### 5.2 文本输入与剪贴板识别

- 提供文字输入框。
- 打开 App 时检测剪贴板中是否存在可解析的文本,询问用户「识别到一段文本,要解析成计划吗?」,用户确认后粘入对话。

### 5.3 计划 / 任务 / 大目标结构

- **大目标**:用户可建立长期目标,并提供完成进度展示。
- **每日任务**:单次任务,可勾选完成,可挂靠到某个大目标。
- **每日重复任务**:如「每天晨跑」,支持重复粒度(每天/每周几/任意日期)。
- **排期边界**:支持未来任意一天安排;支持基于相对时间表达(今天/明天/周X/X号/晚上X点)的解析。

### 5.4 软约束专注计时(优先级 2)

- 番茄钟式倒计时,时长由用户设定;计时结束仅提醒,不做技术强锁。
- 专注结束后提示用户记录刚做了什么,确认后进入休息;休息时长不受限。

### 5.5 复盘提醒(优先级 2)

- 每晚约 23:00 提醒用户复盘今日:哪些做得好、哪些值得鼓励。

### 5.6 场景化提醒(优先级 2)

- 通勤 / 睡前 / 学习高峰时段的防分心提醒(基于时间或位置规则的提示)。

## 6. 范围分层

| 分层 | 内容 | 目标 |
| --- | --- | --- |
| Chunk 1(MVP) | 对话式自然语言→计划、备忘录、剪贴板识别、打勾与进度、大目标 | 验证「自然语言转计划是否真比手动建待办省心」 |
| Chunk 2(P1) | 软约束专注计时、专注结束复盘、通勤/睡前提醒、晚间复盘 | 补上自律闭环 |
| Chunk 3(P2/远期) | 系统级强锁机、流量过滤、慈善捐款退出机制、系统 Agent 深度集成 | 增强控制力 |

### MVP 验收标准

- 用户连续使用后,**解析结果基本不需人工修正**,或修正成本明显低于手动建待办。
- 「对话式确认」能被理解并顺畅操作(产生、修改、确认、转备忘录)。
- MVP 关键路径(输入→对话确认→落地→打勾)无致命卡顿。

## 7. 关键用例(Use Case)

**用例 1:一次性规划一天**
1. 用户输入:「明天上午医院复查,下午写周报,晚上8点跑步。」
2. 系统在对话中产出 3 条草稿(含日期、时段、标题)。
3. 系统追问:「周报大概需要多久?跑步要不要设为每日重复?」
4. 用户回答补充,草稿更新。
5. 用户输入「确认」,3 条正式写入今日计划。
6. 到点提醒;用户打勾完成;

**用例 2:剪贴板识别**
1. 用户复制一段文字后打开 App。
2. 系统检测剪贴板有可解析文本,询问是否解析。
3. 确认后文本进入对话,走与用例 1 相同的确认流程。

**用例 3:写入备忘录**
1. 用户输入:「后天要带身份证,记得买洗衣液。」
2. 系统判断不属排期内容,建议存入备忘录,用户确认。
3. 内容进入备忘录列表。

**用例 4:冲突提醒**
1. 用户安排两个重叠时段的计划。
2. 系统在对话中提示:「这两项时间有重叠,要把哪一项改时间?」
3. 用户调整,草稿更新。

## 8. 非功能需求

- **性能**:解析单次自然语言输入到产出草稿的云端往返 ≤ 3s(网络正常时);对话切换流畅。
- **离线可用**:正式计划表、备忘录、打勾、进度均本地可离线读写。
- **可扩展**:模块间解耦,便于后续接入系统级锁机 / 流量过滤 / 捐款机制而不重构核心链路。

## 9. 隐私与数据

- 数据**本地存储**为主(Room 数据库),不上传云端。
- 仅当用户在对话中触发解析时,把**当次输入文本**上传云 LLM 用于解析;不批量上传、不留存规划数据于云端。
- 需向用户明示:解析环节将把输入文本发送到第三方大模型服务。

## 10. 风险与假设

- 云 LLM 解析中文时间/日期表达存在误差 → 通过对话式确认 + 可修正缓解(核心风险)。
- 多轮对话状态下草稿状态维护复杂 → 通过明确的草稿生命周期模型控制(写入开发文档)。
- 「软约束」因不防退出,专注有效性与用户自觉强相关 → 预期迭代补强锁机。
- 剪贴板自动读取涉及隐私授权 → 需在 Android 权限弹窗中清晰说明用途。

## 11. MVP 验证指标

- 解析准确率(草稿字段命中率)。
- 平均每条计划用户修正次数(越低越好)。
- 生成后仍被保留并执行的计划占比(留存率)。
- 对话框 → 正式写入的使用频次;备忘录使用频次。
- 用户主观评价:是否比手动建待办更省心(访谈/评分)。
